## Limits and follow-up checks

The walkthrough demonstrated ordinary file writes/read-back, nested-root template use, evidence links, linked recovery, and partial-report handling. It did not demonstrate recording a new live user correction before the subsequent action, forced interruption/resume, or prompt-only autonomous compliance. Historical corrections were captured late and must not be presented as a successful capture-delay result.

Claude and Cursor were not run interactively for behavioral validation. Vendor asset composition passed, but actual instruction-following, capture overhead, and independent human judgments of recommendation usefulness remain unmeasured. Calendar boundary selection, late Git discovery, overlapping reruns, and default-window advancement are specified in skill instructions; their complete behavior needs an actual period-review pilot rather than a simulated journal runtime test.

For a team pilot, invoke the generated skills normally, introduce a new correction and a verification failure, interrupt/resume a task, and review a period containing several tasks. Compare saved excerpts and timing with the visible interactions; verify adjacent-window membership, late discoveries, and the effect of partial/filtered reports on “since the last retro”. Record misses and human judgments, then refine the shared instructions without changing capture into a separate user command.
