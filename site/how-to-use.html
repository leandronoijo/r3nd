Context

Generate local context.

Preferred path: run the generated analysis skills inside your favorite coding tool. Secondary path: use the CLI directly.

Preferred: generated skills

  • analyze-repo-context: repo-level map. Input: repo root, usually ..
  • analyze-app-context: app-level guidance. Input: app root, for example apps/backend.
  • analyze-module-context: module-level guidance. Input: module path, for example apps/backend/src/modules/auth.

Secondary: CLI

r3nd analyse
r3nd agents analyze-repo-context --input . --agent codex
r3nd agents analyze-app-context --input apps/backend --agent codex
r3nd agents analyze-module-context --input apps/backend/src/modules/auth --agent claude

These commands generate AGENTS.md and CLAUDE.md at the appropriate scope.

Scopes

Repo, app, module.

Repo scope gives the whole-codebase map.

App scope gives one service or app its own local guidance.

Module scope sharpens context for a single bounded area.

Config

Control the framework with r3nd.yaml.

Config is not an afterthought. It controls which seed to pull from, which overlays are active, and how worktrees behave.

Common keys

seed-repo: leandronoijo/r3nd@develop
overlays: []

worktree-copy-files:
  - "*.env"
  - "**/*.env"

worktree-open-command:
  - code
  - "{worktreeDir}"

What it controls

  • Seed repo: where updates and overlays come from.
  • Ordered overlays: later overlays can override earlier ones.
  • Worktree behavior: what gets copied and what opens after creation.

Worktrees

Parallel AI work, safer.

Create repo-scoped worktrees, copy the right files, and open them however your team prefers.

1

Basic commands

r3nd worktree
r3nd worktree --branch auth-investigation
r3nd worktree clean
2

Defaults

worktree-copy-files:
  - "*.env"
  - "**/*.env"

worktree-open-command:
  - code
  - "{worktreeDir}"
3

tmux or VS Code

worktree-copy-files:
  - "*.env"
  - "**/*.env"
  - ".gitignore"

worktree-open-command:
  - sh
  - -lc
  - |
    worktree_dir=$1
    branch_name=$(git -C "$worktree_dir" rev-parse --abbrev-ref HEAD 2>/dev/null || basename "$worktree_dir")

    if [ -n "${TMUX:-}" ]; then
      pane_id=$(tmux split-window -P -F "#{pane_id}" -c "$worktree_dir")
      tmux select-pane -t "$pane_id" -T "$branch_name"
    else
      code "$worktree_dir"
    fi
  - sh
  - "{worktreeDir}"

Workflows

Pick the right path.

The difference between workflows is not just speed. It is which artifacts exist, where humans approve, and how the agent verifies.

Full control

All stages

Product spec, tech spec, build plan, implementation, test cases, E2E, manual QA, retro. Human approval between stages.

Semi-control

Less ceremony

create-tech-spec and implement-feature for clearer feature work.

Quick feature

Small and bounded

quick-feature investigates, writes one plan, waits for approval, implements, and verifies.

Bugfix

Focused repair

bugfix writes a fix plan first, then applies and verifies the repair.

Manual QA

The agent can do it.

Final QA can be executed by the LLM agent itself with real tools.

Humans review the evidence and approve the result.

That keeps approval human while keeping execution with the agent.

Commands

CLI map.

The CLI is an operator layer around the framework, not the framework itself.

Command Purpose
init Initialize the minimal seed structure
scaffold Scaffold a project with ordered overlays
update Update seed components from the configured seed repo
analyse Generate scoped AGENTS.md / CLAUDE.md context
agents Run task skills for specs, plans, implementation, QA, and analysis
tools Show locally available AI backends
config Manage r3nd.yaml values
worktree Create, open, and clean repo-scoped worktrees
r3nd

Framework first. Tooling second. Repo memory always.
